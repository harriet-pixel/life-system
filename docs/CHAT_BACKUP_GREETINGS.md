# 聊天備份與三句招呼（2026-10-31）

目前完整備份（本機明文／AES加密／手動Drive）含仍有效的user與已正式發布assistant全文。聊天仍獨立IndexedDB，不加入dataStore、長期history或一般Undo快照；只有明確備份才按expiry索引讀取，超過10000回合完整阻擋，保留原資料。聊天快照另在payload.chats，嚴格驗證角色身份、訊息類型、長度與原24小時到期時間；舊版無此欄位仍可讀取。已過期user不使仍有效的assistant丟失。

## 分類排除評估

本次未採用「我的資料、夥伴資料、聊天預設不備份／不覆蓋」：角色身份、切換史、好感度來源、打卡／錢包交易與復原鏈交互引用，混用不同快照可能失去身份或撤回證據；使用者與角色圖片也可能由有效Undo引用。保留完整快照能直接驗證來源一致。排除三類文字未必減少主要圖片成本；僅減少保留版本也主要改善儲存量，不會消除新備份的上傳與完整回讀。

尚未實作的優化建議：

- 顯示打包、上傳、回讀驗證各階段進度與耗時，先找實際瓶頸。
- 將內容雜湊圖片改為只上傳一次的獨立資產，版本存manifest；必須另設跨版本引用及安全清理機制。
- 在Worker壓縮與計算雜湊，減少主執行緒停頓；須保留舊版格式與完整性驗證。
- 若仍要分類還原，先設計各分類獨立版本、依賴清單與衝突預覽，不能只刪除JSON欄位或合併最新值。

## 首頁與招呼

桌面首頁當前頁名至歡迎文案列間距1em。待辦／習慣初始對話空白，僅正式行動回應，不在進頁生成招呼。每角色四時段各三句，表單十二欄；保留舊字串讀取，明確保存才轉新陣列。每角色／時段以sessionStorage索引依序輪播，返回／重新整理首頁前進一次，不因一般數值更新輪播。首頁浮窗與桌面共用同次文字。

AI星光一次生成十二句，greetings purpose輸出上限1024，其他一般生成仍256。完整驗證三句不同且非空才填草稿，失敗／取消／身份、人格、階段或epoch變動保留原資料。提示帶當前人格、由好感度換算的關係stage及該階段的style（態度／語氣等設定）；不傳原始好感度分數、不傳全部階段、不傳聊天全文或帳本。
