## 單次簡述、分配重用與多選安排

每日名稱選單的編輯提供單行簡述，保存於 `occurrences.brief`，不改共用定義；移動跟隨安排，新安排空白。完成時快照至 `completions.brief`，歷史依當時內容呈現；首頁今日清單也安全顯示同筆簡述，待辦池仍僅名稱。舊欄位缺省為空，不改資料版本或清空舊紀錄；驗證拒絕非文字與換行，備份／還原及 Undo 快照共用同一驗證。

固定分配取代完成時依內容匹配快取：`definition.fixedAllocation={points,abilities,source}`，source 為 ai／manual／history。建立重複事件由 `task-fixed-editor.mjs` 提供 AI推薦與五項0～3單選；AI只依名稱、分類及點數提議，使用者可調整，儲存即確認。AI未設定／忙碌／失敗／無效時直接手動，不換商、不重試。推薦前後比較判斷依據與表單編輯世代、來源定義版本，關閉／切頁或人工設定後的晚回應不覆蓋新草稿。名稱／分類改變不自動推薦；點數改變需有效新總和，不能按舊分配保存。

舊格式缺欄位仍可驗證讀取：`fixedAllocationFor` 先用已存設定，否則找同定義最新有效完成、當次實際五項分配且點數等於目前點數。`catchUp` 投影補固定設定，再沿共用 reconcile 或後續交易保存，避免直接修改快照破壞舊 Undo 相依鏈。沒有可信分配者，編輯可補設；若僅修改舊事項而尚未碰分配，可保留未設定，首次完成才走既有 AI／手動流程，成功時在同筆獎勵交易保存固定設定。取消／失敗不保存新分配。固定設定須通過五項非負整數及總和驗證，納入既有備份／還原與跨分頁。

後續完成以共用 service 的固定設定為準，即使呼叫者傳其他分配也不更改實際設定；不再呼叫能力AI，也不因簡述、名稱或分類改變而重判。每次獨立 completion.reward 保存真實貨幣／經驗／能力及當時簡述；設定後續調整不重算舊紀錄。取消與刪除按舊快照精確撤回，Undo／Redo仍重用交易。舊 `completion.allocation.basis` 保留作稽核與相容，不再作快取比對入口，來源允許history。

`task-diagnostics.mjs` 的 `taskTimings()` 記錄 queue／allocation／allocation-recommendation／companion／commit 的 durationMs、status、time，最多120筆、只在文件記憶體。queue 記錄既有完成佇列等待；allocation 標示fixed時只讀設定，不查詢或生成能力。legacy人工分配的allocation包含使用者等待，推薦獨立記錄有效／stale／失敗。companion仍是既有mock、450ms合併後約550ms生成，對話情緒成對更新；完成／獎勵動畫不await它，亦不新增固定停等。沒有金鑰、提示內容或回應原文，無產品除錯欄位、不納入備份。

逾期批次視窗的全選只作用於全部合格、目前列出的穩定執行 ID，部分選取顯示 indeterminate，提交仍重驗資格。常駐任務的安排入口改用 `task-multi-schedule.mjs` 跨月多選月曆；既有安排及終止例外禁選，起訖限制不自動延長。跨月保留選取，可清除、取消，確認透過 `arrangeMany` 先檢查整批，再以一次交易保存；任一衝突完整拒絕，Undo／Redo 一次處理。其他既有單次改期不變。

## 週期與歷史

開始日期預設建立當日，結束日期可空白，星期可全部不選。未來自動安排僅按查看日期推算，不預建多年資料。啟動、重新取得焦點、回到頁面及每分鐘檢查當地日期；每筆定義以 `checkedThrough` 從開始日補算到昨天，不限離線天數，不漏過未開啟日期。補算一律建立待處理紀錄，不發獎；不再自動略過。舊 overdue=skip 僅保留讀取相容，catchUp 將定義改為 keep，忽略舊設定；Undo 重新帶回 skip 也不啟用略過。既有 done／skipped／moved／deleted 狀態不改、不重生、不補發獎勵。跨日後跟隨今日的清單隨當地今天更新為今明兩日，月曆原本停在當月時亦換月；手動選定中心日期及刻意瀏覽的月份保留。逾期判定由共用 isOverdue 管理：pending 且安排日期早於當地昨天，才進池；昨天不出現在逾期查詢、數量或批次範圍。原訂／安排日期不變、不略過、不發獎；跨日與重新開啟／聚焦重新判定。所有待辦交易提交前補算必要紀錄，使新增過去日期也立即顯示在正確區域。

日期以本機年／月／日與中午日期運算，未使用 UTC 的 ISO 日期截取。自動及手動安排可並存；單次移動留下 moved 例外，略過／刪除也永久保留執行狀態。原訂日期在多次移動後仍保留。刪除定義為軟刪除，保留完成歷史、當次獎勵及必要引用。常駐庫有效性採 inResidentLibrary 投影：結束日當天仍顯示，隔天隱藏，保留定義與所有紀錄；不需要資料遷移或背景硬刪除。補算止於 end，離線到期也不生成之後的自動安排；延長已到期 end 時從原 end checkpoint 補齊缺少安排，沿單日唯一 ID 不重生例外。變更週期先依舊規則補算過去，再讓未來採新規則；已存在的未完成紀錄仍可處理並套用最新名稱、分類及點數。

完成保存在 `completions` 的名稱、分類文字、點數、實際貨幣／經驗／五項分配、交易 ID 與取消時間。完成、數值和能力以同筆交易寫入，取消分配不寫入。Redo 套保存快照，不重新呼叫 AI。AI 結果須恰有五個能力 ID、非負整數且總和符合點數；無法設定、失敗或無效時使用手動視窗，不自動換商／重送。手動五項能力各有獨立 0～3 radio，預設及可重選 0；提示已分配／總點數、不足或超出，總和相符才啟用確認。選擇不會改動其他能力，提交仍使用 allocation 驗證與同一完成交易；取消不寫入。

取消完成採保守相依規則：原完成交易必須仍在共用有效復原鏈（七天且最近 15 筆），且當前數值須與該次交易後數值完全相符。否則顯示期限或相依變更原因並保留原狀。反向交易扣實際獎勵，禁止不足額或低於既有安全下限；取消後重新完成採最新設定，並保存新的完成紀錄。長期完成資料不因短期快照到期而刪除。

已完成刪除是另一個新操作，不借用原完成 Undo。prepareDeletion 核對長期 completion 與原 task.completed history 的非撤回狀態及金額、經驗、能力差額；有實際能力時拒絕矛盾明細。舊紀錄能力缺失但完整交易差額可還原時，直接使用真實歷史，不問 AI。只有兩處皆無能力才用完成當時名稱／分類／點數提出推估；有效 AI 回覆也必須顯示「推估」讓使用者確認或改動，失敗／未設定用同一 radio 手動確認，取消不變更。總量無法核對、能力只剩部分或矛盾資料時阻擋並要求補足，不用目前定義猜測。

deleteCompleted 提交前再次核對 revision、完成 ID、原始交易與未撤回狀態，依當前貨幣、內部經驗與每項能力是否足額完整扣回；經驗最低100、貨幣及能力最低0，不截斷。獎勵是可加減的共用累積值，後續獨立操作不要求和過期快照完全相等，但原交易、狀態與足額證據須齊全；不滿足則不刪除。等級由共用 validateStats 重算。交易同時寫入 deleted 例外、cancelledAt 及 retraction（反向交易ID／時間／實際 reward／recorded、history 或 estimated-ai、estimated-manual 來源），一次性定義軟刪除，重複僅刪選定日期。原完成與撤回明細長期保存；新操作受既有七天／15筆與相依鏈 Undo／Redo，Redo 直接重用結果。原方框取消完成仍保留前述保守限制。備份同時驗證原完成與反向交易差額，缺少或不一致整份拒絕。

## 相容、外觀與規模

舊文件／舊備份缺少 tasks 時補空集合；既有 activities（包括 task-0 等示意勾選，以及未知使用者活動鍵）全部保留、不轉成正式事項、不灌入示意資料。首頁只改接正式今日待辦，其示意習慣及固定示意日期仍保留。既有頁籤捲動、雙面板高度與夥伴布局不變。

tasks 已納入共用驗證、七天復原政策、本機和 Google Drive 的相同備份管線；舊備份原始 dataCount 先驗證，再遷移。所有新舊還原先完整驗證，無效文件不部分覆寫。事項編輯使用共用 draft lock，未儲存時阻擋備份／還原等維護。發布的模組 URL 一致更新，避免暖快取把舊的資料白名單與新頁面混用。

無事項數量上限；待辦池每區先呈現 40 筆、每日行程先呈現 30 筆，提供顯示更多，並以索引查詢及分頁控制初次 DOM 數量。資料受既有瀏覽器容量及備份大小保護，寫入失敗保留整份原資料。桌面拖曳使用原生 DataTransfer；待辦池仍可拖曳到每日清單，也保留日期視窗安排操作。每日清單只顯示方框與名稱；方框才完成／取消完成，名稱是獨立按鈕，開啟編輯／刪除此日／刪除整個重複事項的對話框。已完成單次刪除先確認精確撤回；刪除整個定義保留完成歷史。

## 表單鍵盤與儲存效能

`task-dialog-viewport.mjs` 統一依 visualViewport.height／offsetTop 定位待辦 dialog，鍵盤開啟時縮減外框，不以底下頁面捲動避讓。固定高度頁籤仍保留；鍵盤模式壓縮標題留白，底部操作列隨表單內容捲動、不 sticky。聚焦時僅捲內層容器，讓標籤及欄位可見；200%文字或極短高度時退回整窗捲動。鍵盤收回還原正常樣式。共用 navigation-size 對正在編輯的 task-dialog 不再呼叫 window.scrollBy，其他頁面維持。

儲存入口立即顯示「儲存中…」與 aria-busy、阻止重複提交；寫入成功才關窗及通知，失敗保留草稿。一般儲存不等待推薦、夥伴、動畫或網路。`save-diagnostics.mjs` 僅記憶體保留最近30筆耗時，含驗證、鎖等待、正式寫入／復原檢查、序列化、訂閱者、重畫、關窗與通知，不保存欄位內容、金鑰或回應。`saveTimings()` 可供診斷，沒有一般介面除錯文字。

共用 store 快取同一不可變 state 與期限內的唯讀復原檢查，對外資料仍複製隔離；到期、時鐘倒退及 state 更新會重新驗證。每次正式寫入仍在原跨分頁鎖下重新讀儲存版本、驗證完整資料及復原鏈。`changesOnly` 訂閱僅略過 busy 開關的通知，實際資料或顯式跨日 notify 仍通知；Undo控制維持原 busy 訂閱。量測方法與限制見 [SAVE_PERFORMANCE.md](SAVE_PERFORMANCE.md)。
