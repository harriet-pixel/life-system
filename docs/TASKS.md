## 共用入口與資料

- `tasks.html`、`assets/tasks.mjs`：沿用 app-shell 的常駐導覽、跨頁 DOM／草稿、1024px 斷點與 appearance 四種字型。桌面只保留上方頁面識別，手機保留黑色標題。主要入口及新增表單稱「新增事件」。清單固定顯示選定日前一天、當天、後一天，預設以今天為中心；「今日」回當月並重設今天為中心。桌面月曆展開在左；手機預設收合，由操作列月曆 icon 控制，展開於操作列與清單之間。月份箭頭只改月曆，不改清單；今天以 aria-current/date 外框標示，選取日期另有填色。不提供週導航、七日列、週清單或跳至日期。手機月曆開關不改清單日期，具 aria-expanded 與 aria-controls。待辦池保持可收合及既有管理功能。
- `assets/task-editor.mjs`：點數及類型直接以 radio 單選；既有事項類型仍固定。名稱旁日期按鈕開啟獨立日期視窗，可設定／清除；選擇只改草稿，儲存時才與事項一起交易。每日圓形＋預帶當日。點數文字僅 <450px 隱藏「點」單位，radio 值及可存取名稱保持 1點／2點／3點；名稱與分類使用共用 task-form-field／task-field-label 間距。重複事項的額外日期可新增、移動或清除，保留單次例外與自動週期。
- `assets/task-categories.mjs`：主窗只含分類清單、44px 編輯／刪除 SVG icon、並排的新增分類／關閉。新增或編輯使用另一個獨立對話框，先關閉主窗但保留草稿 lease；儲存成功或取消後返回主清單，依分類 ID 還原編輯觸發焦點，取消不寫入。任一時間只有一個開啟的分類 modal。新增／修改名稱與顏色／刪除。表單僅選分類，不再建立分類。操作經共用交易與復原。
- `assets/tasks-model.mjs`：當地日期、版本 1 結構驗證、日期投影、逾期補算與單日唯一性。
- `assets/tasks-service.mjs`：所有變更經唯一 `dataStore.transact`，與 Web Locks／revision 衝突保護共用；批次先在副本驗證，任一衝突不寫入。
- `assets/task-actions.mjs`：首頁和待辦頁共用 AI／手動分配與取消完成；AI service 和共用語言提示不變。等待生成不持資料鎖，提交要求相同 revision、事項版本、點數及當地日期。任一變更即拒絕舊結果，需使用者重新操作。
- `assets/task-companion.mjs` 與既有 `companion.mjs`：成功的新增、編輯、分類、安排、刪除、批次、完成及取消完成才發事件，450ms 合併、舊回應失效、對話／情緒一起更新。日期瀏覽和自動逾期整理不生成對話。

唯一文件仍是 `life-system.data.v1`。新增 `tasks`，內含 `definitions`、`categories`、`occurrences`、`completions`。未指派分類以 null 保存，畫面顯示「未定義」。未新增第二份 localStorage 數值或待辦來源。

事項 ID 在建立時固定；一次性執行 ID 為事項 ID，重複執行為 `事項ID@YYYY-MM-DD`。同日完成、例外與手動／自動安排共用此身份，目標已存在（包含略過／移動例外）時明確拒絕，不能靜默合併。一次性／重複性在建立後固定；需要不同類型時新增另一事項，避免變動身份與獎勵意義。

## 週期與歷史

開始日期預設建立當日，結束日期可空白，星期可全部不選。未來自動安排僅按查看日期推算，不預建多年資料。啟動、重新取得焦點、回到頁面及每分鐘檢查當地日期；每筆定義以 `checkedThrough` 從開始日補算到昨天，不限離線天數，不漏過未開啟日期。補算一律建立待處理紀錄，不發獎；不再自動略過。舊 overdue=skip 僅保留讀取相容，catchUp 將定義改為 keep，忽略舊設定；Undo 重新帶回 skip 也不啟用略過。既有 done／skipped／moved／deleted 狀態不改、不重生、不補發獎勵。跨日後預設三日清單隨當地今天更新，月曆原本停在當月時亦換月；手動選定中心日期及刻意瀏覽的月份保留。逾期判定由共用 isOverdue 管理：pending 且安排日期早於當地昨天，才進池；昨天不出現在逾期查詢、數量或批次範圍。原訂／安排日期不變、不略過、不發獎；跨日與重新開啟／聚焦重新判定。所有待辦交易提交前補算必要紀錄，使新增過去日期也立即顯示在正確區域。

日期以本機年／月／日與中午日期運算，未使用 UTC 的 ISO 日期截取。自動及手動安排可並存；單次移動留下 moved 例外，略過／刪除也永久保留執行狀態。原訂日期在多次移動後仍保留。刪除定義為軟刪除，保留完成歷史、當次獎勵及必要引用。變更週期先依舊規則補算過去，再讓未來採新規則；已存在的未完成紀錄仍可處理並套用最新名稱、分類及點數。

完成保存在 `completions` 的名稱、分類文字、點數、實際貨幣／經驗／五項分配、交易 ID 與取消時間。完成、數值和能力以同筆交易寫入，取消分配不寫入。Redo 套保存快照，不重新呼叫 AI。AI 結果須恰有五個能力 ID、非負整數且總和符合點數；無法設定、失敗或無效時使用手動視窗，不自動換商／重送。

取消完成採保守相依規則：原完成交易必須仍在共用有效復原鏈（七天且最近 15 筆），且當前數值須與該次交易後數值完全相符。否則顯示期限或相依變更原因並保留原狀。反向交易扣實際獎勵，禁止不足額或低於既有安全下限；取消後重新完成採最新設定，並保存新的完成紀錄。長期完成資料不因短期快照到期而刪除。

## 相容、外觀與規模

舊文件／舊備份缺少 tasks 時補空集合；既有 activities（包括 task-0 等示意勾選，以及未知使用者活動鍵）全部保留、不轉成正式事項、不灌入示意資料。首頁只改接正式今日待辦，其示意習慣及固定示意日期仍保留。既有頁籤捲動、雙面板高度與夥伴布局不變。

tasks 已納入共用驗證、七天復原政策、本機和 Google Drive 的相同備份管線；舊備份原始 dataCount 先驗證，再遷移。所有新舊還原先完整驗證，無效文件不部分覆寫。事項編輯使用共用 draft lock，未儲存時阻擋備份／還原等維護。發布的模組 URL 一致更新，避免暖快取把舊的資料白名單與新頁面混用。

無事項數量上限；待辦池每區先呈現 40 筆、每日行程先呈現 30 筆，提供顯示更多，並採 content-visibility 與索引查詢。資料受既有瀏覽器容量及備份大小保護，寫入失敗保留整份原資料。桌面拖曳使用原生 DataTransfer；待辦池仍可拖曳到每日清單，也保留日期視窗安排操作。每日清單只顯示方框與名稱；方框才完成／取消完成，名稱是獨立按鈕，開啟編輯／刪除此日／刪除整個重複事項的對話框。已完成的單次刪除停用，須先安全取消完成；刪除整個定義保留完成歷史。

本次單元測試涵蓋分類顏色與舊資料、清除日期、批次衝突、歷史獎勵、統一逾期及既有共用服務。瀏覽器驗證含 449／450／451px 的九種寬度、四種字型、200% 文字、分類管理、方框／名稱隔離、日期視窗焦點、重複例外、跨年午夜、首頁同步、跨分頁與 AI 備援；另檢查既有頁面、還原及暖快取升級。原生手機鍵盤僅以短視窗模擬，未以實體裝置驗證；未使用真實 AI 金鑰或 Google Drive 授權。

分類顏色可為 null／缺省（使用既有文字色），或 #RRGGBB；沿用共用 luminance 計算，對白底至少 4.5:1，拒絕淺色及非十六進位值。每日名稱使用目前分類顏色，不新增標籤／色塊，也不修改完成歷史中的名稱、分類文字或實際獎勵。刪除分類只將定義的 categoryId 設 null 並增加版本；完成紀錄不變。既有備份缺色可讀，新備份及快照會驗證顏色，無效資料整體拒絕。

一次性清除已存在的 pending 安排會保存 unarranged 狀態及原訂日期，回到未安排池；重新安排或池內直接完成會沿用唯一 ID。重複性清除單次日期留下 deleted 例外，不影響下一週期。日期變更、事項設定與必要例外在同一交易提交，衝突整筆不套用。
