# 夥伴第四階段：情緒圖片驗證

來源基準：開始時遠端 main 為 `f48b1d5f074cd3e99ceee60092d22398dbb8230a`，工作區乾淨；明確 fetch gh-pages（原 remote fetch 僅追蹤 main）後確認為 `2c66dd2`。六頁及 assets 與來源一致，沒有發布分支獨有修正。只接續既有網站。

## 實作與界線

八個集中定義的情緒 ID：neutral、happy、calm、thinking、surprised、concerned、determined、playful。未知 ID 安全退回 neutral；開發邊界可用 mockEmotionId 把 pleased 對映 happy，原 mock 與好感度算法不變。正式聊天室仍停用，無聊天資料、AI、回覆庫、首頁招呼、新後端或背景上傳。

角色新增選填 imageSettings：version:1、revision、emotions。每情緒為 image／thumbnail（asset:SHA256）、crop、updatedAt；由角色穩定 characterId 與固定 emotionId 關聯。人格 configVersion 與圖片 revision 分離，不更動好感度或出場歷史。舊角色缺圖片欄位仍原樣可讀，不靜默寫入空圖片或改變原人格。保守地對整位角色圖片設定檢查 createdAt＋原完整圖片設定，避免跨分頁／還原覆寫；不同情緒的同時修改也會提示重新讀取，而非猜測合併。

裁切 x、y、size **全部以立繪寬度為單位**，因此 y+size 最大 4/3、x+size 最大1；size 最小0.05。正方形不依賴螢幕像素。每情緒各自保存，不另存頭像 Blob。圖片列表使用120×160縮圖，聊天室頭像亦使用該縮圖套用相同相對裁切；完整圖只用於桌面立繪或開啟的管理視窗。

原檔12 MiB、2400萬像素、單邊12000px，PNG／JPEG／WebP；先讀內容標頭和尺寸，拒絕 SVG／GIF／動畫，再實際解碼。createImageBitmap 可用時非同步解碼，24MP 上限限制峰值；無此能力以瀏覽器 Image.decode 備援。尊重瀏覽器 EXIF 方向，不用原標頭尺寸強拉解碼比例。只在上傳時預處理到2048px以內；確認立繪裁切才輸出3:4、最長1600px、最多1MiB，保持透明。重用 avatar-crop 的裁切器與編碼器，新增可選 ratioUnit 保證壓縮降尺寸仍精確3:4；不改既有使用者裁切行為。Canvas／Bitmap／臨時URL用後釋放。

管理分區在角色設定中，只有既有兩主頁籤。卡片進入單一原生dialog：置中、標題／✕、上傳、3:4拖曳／縮放／方向鍵、確認後實際結果、可拖曳及角落縮放正方形、細部範圍控制、即時圓形預覽、保存／取消／刪圖。遮罩／Escape／✕離開有草稿確認；固定視窗首尾、內文捲動，還原觸發焦點。站內路由保留同一dialog草稿，處理中沿外框busy阻擋切頁；真正離頁用既有beforeunload。取消不動正式圖片。封存保留圖片；永久刪除只移除正式引用與保留角色tombstone，不立即刪Blob。neutral有缺圖依賴時不能刪，需替換；非neutral刪除後固定分類仍存在。

桌面沿原3:4框；手機不顯示大圖。頂部頭像永遠取neutral，每訊息顯示器各自接收其emotionId，不用最新情緒覆寫其他頭像。載入失敗依序退neutral與原生占位。顯示器公開 show(character,emotion,transition) 能力供測試／後續使用，正式聊天室沒有測試按鈕。圖片讀取採序號失效，快速切換舊結果不覆寫新角色；最多兩層加一個待載URL，離頁／替換釋放。新圖片decode成功後才覆蓋，opacity250ms或直接切換；reduced-motion強制直接。全站選擇存settings.companionImages.transition，選擇即保存，缺省fade；舊資料與備份不必新增此欄位。

## 安全、引用與備份

仍用唯一 life-system.data.v1 與既有 life-system.images.v1/images，不存base64於共用文件。內容雜湊去重；只有立繪及小縮圖各一份，無八份頭像。image-store 新增讀Blob、Blob入庫與明確擁有／釋放的URL API，獨立於原使用者URL生命週期，不會因關閉夥伴頁誤撤銷個人立繪。

兩階段：處理完成先保存Blob（既有24小時暫存保護），再核對資產存在、雜湊、解碼、尺寸、裁切、角色及原圖片設定，經既有dataStore交易／Web Lock／revision提交。服務本身持有既有companion草稿鎖至提交完成；視窗亦持有同類共享鎖及圖片引用來源。提交失敗保留舊圖和可重試草稿，新資產受暫存保護，之後只可手動清理。其他分頁刪除角色不會復活。

image-references只掃明確imageSettings.emotions的image、thumbnail，不掃人格文字，格式無法辨識則停止清理／備份。原使用者、最愛、復原、草稿及雲端待處理鎖仍保留。圖片操作不納入短期Undo，避免復原整個companion而回溯出場歷史／復活刪除角色；其他Undo／Redo不變。

明文、加密與手動Drive沿原備份服務自動包含正式角色圖片、縮圖及全部裁切／版本。讀取備份驗證圖片集合、雜湊、內容、尺寸與完整引用，再寫入IDB，最後單次發布文件；restoreBackup亦重查必要圖片可用與內容完整，缺圖或提交失敗不取代原文件。舊備份仍可還原，沒有圖片欄位即回到無圖狀態。雲端仍只有「上傳雲端」，沒有背景或自動上傳。

## 效能與快取

首頁無圖片管理器、顯示器、裁切器或角色圖片讀取；只新增共用驗證必需的輕量定義／完整性函式。角色頁不替未查看角色建立圖片DOM；圖片區收合時不讀8張圖，展開只讀小縮圖，完整編輯圖只在視窗開啟後解碼。顯示與編輯模組分開動態import，無AI、輪詢或無界快取。所有圖片處理僅在使用者操作時執行。

共用驗證改動必須讓舊HTTP快取失效，因此更新實際相依圖的版本查詢字串及六頁shell版本；多數既有模組與測試差異僅import URL，未改原數值算法。暖快取驗證使用確切第三階段HTML與資源，再切換本次建置。
